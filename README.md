# Живой город — v3

Постоянный многопользовательский RP-город, который жители строят и обслуживают сами.
Основано на идее Михаила от 18 ноября 2026 года (Europe/Moscow).
Название временное. Российский сеттинг и стиль town-v2 утверждены; ракурс panel-v2 и отделка panel-v3 утверждены.

## Статус

В client/ работает одиночная сцена: ходьба, камера и первый строительный заказ с покупкой материалов, ремонтом дороги, оплатой и местным сохранением. В отдельном онлайн-стенде работают два гостевых игрока. Боевая версия gorod.michaelperov.com использует вход по почте через хаб, общий город, серверное сохранение и установку PWA; см. docs/HUB-ACCOUNTS.md. Концепт в `art/concepts/` — иллюстрация направления,
а не скриншот работающей игры. Репозиторий: https://github.com/MihaThePooh/gorod. Рабочая версия закреплена тегом v3; сведения о релизе — releases/v3.json.

## Первая роль Михаила

Городской строитель-подрядчик: дороги, жильё, производственные и общественные
здания. Не мэр и не всемогущий редактор карты. Заказывает материалы, берёт
контракты, работает инструментами, нанимает NPC, сдаёт объекты и получает оплату.
Административный режим разработчика отделён от обычного персонажа.

## Ближайшая цель

Небольшой заброшенный посёлок, два одновременно подключённых игрока,
один строительный контракт, NPC-поставщик, общая сохранённая дорога и журнал
движения денег/материалов. Сначала проверить удовольствие от строительства,
затем добавлять профессии и общественное управление.

Игровой сервер с аккаунтами хаба: https://gorod.michaelperov.com/; гостевое и одиночное превью сохранены. Инфраструктуру действующих VPN и шлюза
проект не затрагивает.

## Сборка рабочей игры

Требуется Python3.12. Зависимости проверки входа: `pip install -r requirements.txt`.

```sh
python3 tools/build_hub_client.py --base-path / --out .gorod-client-v1
python3 -m unittest discover -s test -p 'test_*.py'
node --test test/construction.test.mjs test/motion.test.mjs
```

Сборка в `.gorod-client-v1/` — это браузерные файлы, не сервер и не база.
`client/` содержит исходную одиночную сцену, из которой собираются отдельные
онлайн-варианты. Браузеру выдаются только файлы из перечня рабочего релиза.
Сервер: `server/online.py`, проверка аккаунта: `server/hub_auth.py`.
Хаб/id — отдельный репозиторий: игра получает только публичные ключи.

Рабочие параметры сервера: `--port 8799 --origin https://gorod.michaelperov.com
--cookie-path / --hub-keys-url http://127.0.0.1:8101/api/keys --tick-seconds 0.05
--snapshot-seconds 0.1 --db <private-path>/towns.sqlite`.
Фактические nginx/systemd и правила backup описаны в docs/HUB-ACCOUNTS.md и
MOTION-SMOOTHING.md. Данные игроков, конфигурация сервера и секреты в Git не входят.

## Версии и дальнейшая работа

Используем простые рабочие версии `v1`, `v2`, `v3` без трёхкомпонентной нумерации.
У каждого опубликованного релиза — запись в CHANGELOG.md, VERSION и отдельный
неперезаписываемый тег. Промежуточные коммиты новую рабочую версию не создают.
После одобрения и выкладки изменения сохраняются в этом же репозитории;
SHA исходников/ассетов релиза позволяет сопоставить его с установленной игрой.
Число `version:1` внутри состояния игры — схема данных, не номер релиза.

Репозиторий хранит исходники, документацию, текущие игровые ассеты, основные
Blender-модели и материалы. Локальные фото/видео-референсы, отвергнутые большие
модели, старые сборки, рендеры и частные базы исключены. Полный переносной ZIP
по правилам docs/BACKUP.md шире Git-репозитория; Git не заменяет backup базы.
Исторические документы отражают состояние на момент написания, актуальные
сведения о версии начинаются с этого README, VERSION и CHANGELOG.md.
